Building the Factory · Campaign 001

I Spent 18 Months Building the Factory. Tonight I Felt It Start to Run.

One AI agent working for hours is not the story. The story is the architecture, evidence, authority boundaries, and operating discipline that make the work useful enough to compound.

Published Sep 30, 2026By Shane StroughStanding Evidence-aware founder field note

Sometime after midnight, I realized I was walking around the house singing.

Not because an AI wrote some code. That stopped being novel a long time ago. I was watching months of systems work begin to pay me back in real time.

One of my coding agents had been working steadily for hours. I joked that it was in there flinging semicolons and SHA hashes off the systems chassis like sparks from a grinder.

The joke stuck because it was funny. But it also exposed the important part.

The agent was swinging the hammer. I had spent roughly eighteen months building the factory around it.

The agent is not the product

It is easy to make the wrong thing impressive in AI development. A model can generate a lot of code. An agent can stay busy for a long time. A terminal can scroll fast enough to look like productivity. None of those things, by themselves, tell me whether the work belongs in a real operating system.

The harder questions are less cinematic: What was the agent allowed to change? What evidence says the change actually happened? What version is running? Did the live behavior match the report? What happens when reality disagrees with the repository? Which decisions still belong to a human? Can I recover the system if the change is wrong?

Those questions are why I kept building infrastructure around the models instead of treating the models as the infrastructure.

Eighteen months of invisible work

The last eighteen months produced applications, yes. But a lot of the important work lives between the applications: repositories and release discipline; a registry of what should exist; a control plane for what actually runs; evidence and lifecycle language; human approval boundaries; agent handoffs; deployment checks; backups; observability; and increasingly, mechanisms for catching the moments when the record and reality disagree.

None of that is as easy to demo as “watch the AI build an app.” It is also the reason I can increasingly let agents perform substantial work without pretending their output is automatically true.

Agents can assert. Reality gets a vote.

One of the principles emerging from the estate is simple: agents may assert; sensors observe; evidence supports proof; doctrine determines what standing that evidence earns; the principal authorizes; canonical records declare.

That distinction sounds academic until something disagrees. Then it becomes operational.

An agent can report that a service was deployed. The runtime can report a different commit. A repository can contain a fix that never reached the machine. A process can be consuming resources even though no declared runtime says it should exist. A login path can be implemented in code and still remain unproven on the actual phone until the real-device check happens.

If all of those things collapse into one word—“done”—the system becomes easy to automate and hard to trust.

So I am building the opposite: an environment that preserves the disagreement until it is reconciled.

Working definition

An agentic software estate is the operating environment around AI workers: applications, infrastructure, repositories, evidence, authority, deployment controls, and durable records that let agentic work become governable instead of merely generative.

This is where the compounding starts

For a long time, architecture work feels indirect. You build systems that manage systems. You write rules for things that appear to work without rules. You record evidence nobody sees. You create deployment controls that make the flashy path slightly slower.

Then one night the accumulated structure starts paying rent.

A specialist can work inside an existing codebase. The estate already knows where that code belongs. The control plane already knows some of the things it may operate. The evidence model already tells us not to promote an agent report into proven reality just because the report sounds confident. The handoff can survive the session. The next worker does not have to rediscover the entire world.

The result is not “AI replaces the developer.” It is closer to industrial leverage: the worker becomes more useful because the environment around the worker has been engineered.

Building the Factory

That is the story I am going to start documenting publicly under a name that finally feels obvious: Building the Factory.

It will include the useful parts, not just the victories: architecture decisions, agent missions, product windows, deployment mistakes, drift, security lessons, recovery drills, governance, digital-twin work, and the moments where something I believed about the system turned out not to be true.

The goal is not to post every day. The goal is to capture real work, preserve the evidence, extract what is transferable, and let the public record compound alongside the software estate.

Eventually even the presenter may be part of the system. I have already been building pieces of my own digital twin—my likeness and cloned voice. When that is good enough to represent me, I want it to become a disclosed media interface to the estate, not a gimmick and not a substitute for my authority.

The factory is not finished

There is still a lot to do. The estate needs stronger runtime-versus-source truth, discovery of undeclared runtimes, better secrets accounting and rotation, restore proofs, cleaner identity unification, durable agent-role records, and eventually deeper coordination across systems.

That incompleteness is part of the point. I do not want to document a mythology where every build is inevitable and every agent run succeeds. I want to document the actual process of making the environment more truthful, more governable, and more useful.

Last night, one agent spent hours swinging the hammer.

For the first time, I could really feel the eighteen months I spent building the factory around it.

Build the factory. Capture the evidence. Tell the truth well. Let the work compound.
